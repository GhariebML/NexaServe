# n8n workflows

Canonical core workflow JSONs are bundled under `assets/n8n/workflows`. Credential definitions and secrets are excluded; non-secret credential references may remain on workflow nodes. The bundle import script does not issue a publish command, but n8n import-state behavior is target-version-specific and remains unverified. The release gate rejects `active: true` exports. Do not infer resulting activation state from an omitted or false `active` field; complete an isolated target-like import acceptance test before approving the export encoding. After import, create the PostgreSQL credential inside the target n8n UI and verify or rebind every database node before any separately approved activation. Also verify workflow IDs, called subworkflow IDs, Ollama URLs, and webhook targets.

n8n uses its dedicated PostgreSQL DB and persistent volume; access its editor via SSH tunnel by default. Public base URL and `WEBHOOK_URL` must match the approved TLS endpoint. Keep encryption key protected. Never import the ignored local credential file.

The output dispatcher must set `settings.errorWorkflow` to `CSWF000000000008` (Global Error Handler & Dead Letter Queue) in both source and package exports; the import path does not add this setting. The other canonical workflows currently do not all carry this setting, so do not interpret this dispatcher-specific gate as a package-wide assertion. After import, bind the approved target PostgreSQL credential to every Postgres node (20 nodes across 8 workflows) before activation. The package contains no credential definitions or secrets; node-level references are not proof that a matching target credential exists or is valid.

The source/package set currently includes six workflows with `active: true`. These exports are intentionally left unchanged until an isolated import acceptance test establishes the supported inactive representation for the pinned n8n version. The offline release validator therefore fails closed and deployment remains blocked.

Script-based activation is not part of import/update. The only script allowlist currently permits the gateway ID `CSWF000000000001`, and it requires both an explicit `--activate-workflow` argument and `N8N_ACTIVATION_APPROVED=true`; the dashboard route has the same gateway-only allowlist and additionally requires `N8N_IMPORT_ACCEPTANCE_VERIFIED=true`. The release validator also requires an inventory `n8n_workflows.import_acceptance` record with `status: passed`, the tested n8n version, and an evidence reference. These controls do not replace production release approvals.
